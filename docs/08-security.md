# Security and privacy

## Security posture

Norn opens logs, repositories, patches, command output, and trace containers
that may be malformed or malicious. All imported data is untrusted. A local
desktop application still needs strict trust boundaries because traces can be
downloaded, shared, or generated by compromised tools.

Version one is offline by default and does not execute trace content.

## Non-negotiable properties

Opening or replaying a trace must never:

- execute a command, script, binary, hook, plugin, or macro;
- checkout or mutate a repository;
- resolve a path outside the selected repository boundary;
- fetch a URL or contact a provider;
- load executable code embedded in a trace;
- render arbitrary HTML or active document content;
- expose unredacted secrets in an export by default.

These properties are enforced in code structure, not only documented as user
expectations.

## Trust boundaries

```text
Untrusted                         Trusted application state
---------                         -------------------------
source JSONL  -> bounded parser -> canonical records
.norn file    -> validator      -> typed trace queries
repository    -> safe reader    -> hashed baseline blobs
trace strings -> text renderer  -> inert glyphs
export path   -> path checks    -> atomic writer
```

Provider records never become format strings, shader source, file paths,
command arguments, or markup without appropriate encoding and validation.

## Path safety

All recorded paths are normalized to repository-relative `/`-separated paths.
Reject:

- absolute paths;
- drive or UNC prefixes;
- `.` and `..` components after decoding;
- embedded NUL bytes;
- invalid Unicode or platform encodings;
- symlink traversal outside the repository during import;
- case-collision ambiguity on case-insensitive filesystems.

When reading a repository baseline, resolve each path beneath an already-opened
repository root and verify the final target remains within it. Import never
follows a repository symlink by default; an explicit option may allow safe
in-root symlinks later.

Replay uses virtual paths and performs no filesystem resolution.

## Parser safety

- All lengths and counts are checked before arithmetic and allocation.
- Integer addition and multiplication use overflow-checked helpers.
- Nesting and recursion have explicit limits.
- Compression has decoded-size and ratio limits.
- Checksums are verified before decoding structured payloads.
- UTF-8 validation is bounded and reports byte offsets.
- Unknown data is skipped by validated length, not scanned for sentinels.
- A parse failure returns an error; it does not partially initialize trusted
  objects.

The parser must be suitable for fuzzing even if the project initially uses
corpus mutation rather than an integrated coverage fuzzer.

## Secret handling

Potential secrets appear in prompts, tool arguments, environment dumps, URLs,
command output, patches, and source files. Redaction occurs during import before
writing the destination trace.

Rules:

- raw-source retention is off by default;
- known credential patterns are replaced with typed markers;
- authorization headers and common secret-bearing fields are always redacted;
- URL user information and configured sensitive query parameters are redacted;
- home-directory prefixes are replaced with a stable placeholder;
- user rules run before canonical interning and blob hashing;
- reports list rule identifiers and counts, never matched values;
- the original source trace is never modified.

Norn cannot guarantee automatic discovery of every secret. The import dialog
states this limitation and offers a redaction preview based on sampled records.

## Visible model content

Norn displays only content recorded by the source trace. It does not attempt to
recover hidden model reasoning, label summaries as verbatim reasoning, or merge
provider metadata into visible messages without provenance.

## Repository privacy

- No network access is required for import, viewing, replay, or export.
- Repository content is copied into a trace only when needed for replay.
- The metadata panel reports how many file-content bytes the trace contains.
- Exports include only selected files and events.
- Recent-file history stores local paths in application preferences and can be
  disabled or cleared.

## Export safety

Before export, Norn shows a manifest of included:

- prompt and response text;
- file paths and diffs;
- command lines and output;
- repository metadata;
- raw or extension records;
- annotations.

The default export applies import redactions again plus export-specific rules.
HTML output uses a fixed template with escaped text, restrictive content
security policy, no remote resources, and no executable JavaScript requirement.

## External actions

Opening an editor, revealing a file in Finder, or opening a URL is an explicit
user action. Arguments are passed as an argument vector to a configured program.
Trace content is never concatenated into a shell string.

## Local state

Application preferences and annotation overlays follow platform-appropriate
user-data locations. Sensitive temporary files use user-only permissions and
are atomically renamed. Import failures remove temporary output where safely
possible; crash leftovers are recognizable by suffix and never auto-opened.

## Reporting vulnerabilities

Before public release, the root repository must contain a `SECURITY.md` with a
private reporting channel, supported versions, response expectations, and a
statement that public issues should not include unredacted traces.
